# DeepLog mobile shells

Capacitor wrappers that package the `web/` app as native iOS and Android
apps. There is deliberately **no committed Xcode or Gradle project here**: both
are generated from `capacitor.config.json` during the build, so there is no
large generated tree to drift or to review.

    mobile/
      capacitor.config.json   app id, name, colours
      scripts/copy-web.js     copies web/ -> www/ at build time
      www/                    generated, ignored
      ios/  android/          generated by `cap add`, ignored

## Building iOS

An iOS build needs macOS and Xcode, so it runs on a GitHub Actions `macos`
runner rather than locally — free and unmetered, because this repository is
public. The **iOS app** workflow runs on demand:

    gh workflow run ios.yml

It produces two artifacts:

- `deeplog-ios-simulator` — a `.app` you can drag onto a running Simulator
- `deeplog-ios-unsigned` — an unsigned `.ipa`

## Getting it onto a real iPhone

Neither artifact will install on a device as-is: iOS refuses unsigned code.
The machine was never the hard part; signing is.

- **Free Apple ID** — re-sign the unsigned `.ipa` with AltStore or Sideloadly
  from a computer. Certificates last 7 days, so it needs repeating weekly.
- **Apple Developer Program ($99/yr)** — add the certificate and provisioning
  profile as repository secrets and the workflow can produce a signed build,
  or upload to TestFlight.

Before paying, note App Store review guideline 4.2 (minimum functionality):
a plain web wrapper is the shape reviewers reject. TestFlight and sideloading
have no such gate. Giving the app something genuinely native — the BLE dive
computer download the Android app already does — is what would make an App
Store submission comfortable.

## Building Android

The repository already ships a native Android app (`app/`) with
libdivecomputer BLE download; that, not this, is the Android app to install.
`@capacitor/android` is not a dependency here for that reason.
